# AGENTS.md

## Engineering Standards for All AI Agents

All AI agents must strictly follow the standards below before performing any coding, file creation, modification, or refactoring task.

### 1. Read `AGENTS.md` First
- Every AI agent **must read this `AGENTS.md` file before starting any task**.
- No implementation, file creation, update, or refactor should begin until these instructions have been reviewed.
- These rules must be treated as the primary operational standard for all agent actions within the project.

### 2. Maintain a Clear and Professional Project Structure
- Always organize files and directories in a logical, consistent, and professional manner.
- Group related files by purpose, feature, or module.
- Use clear and meaningful names for files, folders, classes, and components.
- Avoid clutter, unnecessary nesting, or poorly named directories.

### 3. Keep File Size Manageable
- No single code file should exceed **300 lines** whenever reasonably possible.
- If a file approaches this limit, split the logic into smaller, focused modules.
- Separate concerns properly (for example: utilities, services, components, handlers, and configurations).

### 4. Do Not Place All Code in a Single File
- Never implement an entire feature or system inside one large file.
- Break code into multiple files based on responsibility and maintainability.
- Use modular design so each file has a single, clear purpose.

### 5. Write Maintainable and Scalable Code
- Prioritize readability, maintainability, and long-term scalability.
- Follow clean code practices and avoid unnecessary complexity.
- Ensure the codebase remains easy to navigate, review, and extend.

### 6. Enforce Consistency
- Apply the same structural and organizational standards across the entire project.
- New files and updates must align with the existing architecture unless improvements are required.
- When improving structure, do so without introducing confusion or breaking consistency.

## Compliance Requirement
These rules are mandatory. Every AI agent must follow them in all code generation, file creation, modification, and refactoring tasks.
